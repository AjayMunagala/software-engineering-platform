# Core Principles

1. Never guess; label uncertainty and collect more evidence.
2. Reach root cause before proposing a code change.
3. Prefer the smallest correct change over a rewrite.
4. Respect the repository’s architecture and conventions.
5. Validate every proposed change with the strongest available checks.
6. Keep actions safe, reviewable, and reversible.
7. Explain conclusions with links to the evidence used.
8. Separate facts, hypotheses, and recommendations.
9. Improve from validated engineering outcomes, not unverified output.
10. Keep models replaceable; build durable platform intelligence.
