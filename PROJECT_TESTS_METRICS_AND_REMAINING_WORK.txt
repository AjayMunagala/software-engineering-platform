1. SIMPLE PROJECT STATUS
======================================================================

The platform can currently:

1. Receive a local repository path.
2. Scan its files without using an LLM.
3. apply ignore rules.
4. Detect supported languages, frameworks, build systems, package managers,
   workspaces, lock files, Git information, and repository metadata.
5. Parse Go source code and discover packages, imports, structs, interfaces,
   functions, methods, constants, variables, fields, parameters, results,
   local declarations, labels, and type parameters.
6. Build deterministic Go package-identity evidence.
7. Build deterministic Go semantic information, including scopes,
   declaration reconciliation, receiver/type binding, imports, references,
   interface checks, diagnostics, and explicit unresolved/ambiguous states.
8. Serialize immutable, versioned artifacts that can later be stored.
9. Validate a proposed PostgreSQL artifact schema using real artifacts up to
   the 1.56-GB Kubernetes semantic artifact.
10. Install the frozen PostgreSQL schema through ordered, checksum-verified
    migrations in an isolated PostgreSQL 18 cluster.
11. Persist and retrieve exact immutable artifacts through a storage-neutral
    PostgreSQL adapter candidate with atomic publication and scoped reads.

The Phase 3.3 database migrations are accepted and frozen. The platform does
not yet provide an accepted/frozen production storage adapter, REST/gRPC APIs,
a React UI, an
LLM reasoning engine, patch generation, or patch validation.

IMPORTANT EXPLANATION OF THE "ABOUT 138 GIB" RUN SIZE

During live monitoring, the full benchmark was described as operating at about
the 138-GiB scale. That is a useful approximate description of the overall
large repeated run, but it is not an exact final /proc process counter.

The exact defensible logical stage/read total from the machine report is
125.102 GiB. It excludes manifest hashing, core fixture staging, database
protocol traffic, publication, backup, restore, and verification work.

At a late checkpoint before completion, Linux reported:
  Client read characters: 136,248,602,025 bytes (126.89 GiB)
  Client written characters: 66,656,309,635 bytes (62.08 GiB)
  Combined character I/O at that checkpoint: about 188.97 GiB

These operating-system character counters are not physical disk bytes and can
double-count client/server movement. The final process exited before one last
/proc I/O snapshot was recorded. Therefore:

  - use 125.102 GiB as the exact logical payload stage/read figure;
  - use "about 138 GiB of overall benchmark-scale data movement" only as an
    approximate human summary;
  - do not present 138 GiB as an exact disk-write measurement.

Representation decision:
  256-KiB chunks failed the 50-MiB/s minimum stage gate on large fixtures.
  1-MiB chunks fell to 42.14 MiB/s on Kubernetes and failed that gate.
  4-MiB chunks remained at or above 52.42 MiB/s and passed.

Accepted decision:
  Fixed chunk size: 4 MiB
  Initial operational artifact limit: 4 GiB
  Schema ceiling: 8 GiB
