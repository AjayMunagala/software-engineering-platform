# Project Rules

These rules apply to humans, tools, and future automated components.

1. Never present a guess as a fact.
2. Collect evidence before reaching a conclusion.
3. Understand relevant dependencies and architecture before editing code.
4. Prefer the smallest correct change; do not rewrite whole files without a specific justification.
5. Do not modify code without an authorized scope and a reviewable plan.
6. Do not execute project commands without explicit authorization and captured results.
7. Validate each change with relevant checks; record what did and did not run.
8. Preserve project conventions and architecture unless a deliberate architecture decision says otherwise.
9. Explain reasoning, evidence, uncertainty, and trade-offs.
10. Evidence is more important than model confidence.
11. Protect secrets, private code, and repository boundaries.
12. Record material architecture decisions as ADRs.

If a rule cannot be followed, stop and surface the conflict rather than silently bypassing it.
